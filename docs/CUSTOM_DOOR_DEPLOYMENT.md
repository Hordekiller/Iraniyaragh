## داده و بازیابی پیش از انتشار

backup نهایی با شناسه `20261104T060549Z` روی VPS، با دسترسی محدود، نگهداری شد.
export واقعی یا اطلاعات مشتری وارد مخزن و گزارش عمومی نشد.

- checksum فایل PostgreSQL تأیید شد؛ backup در دیتابیس جداگانه بازیابی شد.
- تعداد ردیف‌های تمام ۱۰۹ جدول نسخه قبل از migration با دیتابیس اصلی تطابق داشت.
- هر ۱۰٬۷۳۸ فایل رسانه با مجموع ۲۲۳٬۳۳۸٬۳۲۱ بایت backup گرفته شد.
- همه فایل‌ها در bucket خصوصی موقت بازیابی و دانلود شدند؛ checksum و metadata
  هر فایل تطبیق داده شد. bucket موقت پس از موفقیت حذف شد.
- دو migration ابتدا با ایمیج رسمی روی همین دیتابیس بازیابی‌شده اجرا شدند، سپس
  روی دیتابیس اصلی اعمال شدند. دیتابیس موقت در پایان حذف شد.

تعداد migrationهای تکمیل‌شده production برابر ۶۹ است؛ migration ناتمام صفر.
داده آزمایشی، مدل فرضی، تعرفه ساختگی یا حساب fixture روی production ایجاد نشد.

## سرویس‌ها و منشأ ایمیج

API، storefront، admin، Nginx، media-worker و pdf-render-worker همگی نسخه
`88bb5832` را اجرا می‌کنند. سرویس‌های HTTP سالم و هر دو worker در حال اجرا
هستند؛ شمارنده restart هر شش سرویس هنگام بررسی نهایی صفر بود.

digest هر شش ایمیج دریافت‌شده دقیقاً با خروجی CI تطبیق داده شد. هیچ build روی
VPS انجام نشد. تنظیمات محیطی، به‌جز ثبت `IMAGE_TAG` نسخه موفق، با fingerprint
پیش از انتشار یکسان ماندند. DNS، Cloudflare، تنظیمات proxy، درگاه و پیامک
تغییر نکردند. داده‌سرویس‌ها و volumeهای فعلی حفظ شدند.

اجرای مرورگر production از API واقعی استفاده کرد؛ کاتالوگ intercept یا Mock
نشد. تصاویر و نتیجه ماشین‌خوان در `/tmp/door-live-evidence` محیط توسعه ثبت شدند.
شواهد عملیاتی خصوصی VPS در فایل‌های `/root/door-latest-restore.log`،
`/root/door-latest-object-restore.log`، `/root/door-release-exact-sha.log` و
`/root/door-postdeploy-images.txt` نگهداری شده‌اند. این فایل‌ها ممکن است در
پاک‌سازی عادی محیط حذف شوند؛ backup محدودشده مستقل از فایل‌های موقت تست است.

یک بررسی اضافی HTTP از محیط توسعه با timeout اتصال TLS روبه‌رو شد. تلاش
مجدد curl به دامنه عمومی پاسخ ۲۰۰ داد و بررسی هر ۱۲ مسیر در origin نیز موفق
بود. این timeout به‌عنوان اجرای اولیه موفق ثبت نشده است؛ سه اجرای کامل مرورگر
روی دامنه عمومی پیش‌تر بدون خطای JavaScript موفق بودند.

## پیکربندی لازم برای فروش

هنگام انتشار، تعداد مدل، متریال و سفارش ساخت درب production صفر بود. مدیر باید
مدل‌های واقعی، قواعد فنی و سازگاری، تصاویر تأییدشده، اجرت، قیمت معتبر و سیاست
بیعانه را از بخش «مدیریت ساخت درب» ثبت کند. تا آن زمان صفحه وضعیت نیازمند
پیکربندی را نشان می‌دهد و سفارش با مدل یا قیمت فرضی پذیرفته نمی‌شود.

رزرو متریال به اتصال SKU با واحد واقعی، محل موجودی و برنامه مصرف معتبر نیاز
دارد. ارسال پیامک تأیید Quote به تنظیم template معتبر وابسته است.

پذیرش پرداخت واقعی بیعانه/تسویه، دریافت پیامک واقعی و بارگذاری فایل توسط
مشتری واردشده در این انتشار اجرا نشده‌اند. تست‌های پرداخت با Mock و صحت
بازیابی storage و اسکن واقعی، این سفرهای کامل مشتری را موفق اعلام نمی‌کنند.
هیچ پرداخت یا پیامک آزمایشی واقعی از طرف ایجنت ارسال نشد.

## بازگشت

ایمیج‌های نسخه قبلی و backupهای قبل از migration حفظ شدند. دستور موجود
`scripts/deploy/rollback.sh` تنها ایمیج‌ها را برمی‌گرداند؛ migration را معکوس
نمی‌کند. بازگردانی دیتابیس اصلی اقدام جداگانه‌ای است و باید نوشتن‌های بعد از
انتشار و تراکنش‌های مالی جدید را پیش از هر restore تطبیق دهد. تاریخچه مالی یا
migration اعمال‌شده برای بازگشت حذف یا بازنویسی نمی‌شود.
