# ایرانی یراق assets

The operator-supplied `5ico.png` remains `source/mark.png`. The wordmark's
display name was corrected to **ایرانی یراق** on 2026-10-26; the previous
operator input is preserved in Git history. Manifest source hashes identify the
exact inputs. All served assets remain local.

The corrected transparent `source/wordmark.png` was edited with the built-in
imagegen tool using the existing print wordmark. Prompt: add the final Persian
ی to the silver word ایران so it reads ایرانی; preserve the blue یراق, metallic
style, hinge icon, tagline and transparent background; clean the alpha edges.
The standalone mark and favicon input were not changed.

`node scripts/prepare-brand-assets.cjs` creates transparent size-specific WebP
for UI and PNG browser/touch icons. Invoice printing preserves the approved
`source/invoice-wordmark-v2.png` bytes separately from UI logo changes.
`--check` verifies both apps' generated bytes against these inputs and manifest.
This uses the existing pinned API sharp dependency. Originals are not served as
megabyte images on small-screen headers.

Web header/footer/customer-login, Admin authentication/sidebar (compact/full),
browser icons and issued-invoice view/print use these assets. Admin URLs include
its configured base path; print fonts are imported into Next's local asset graph.
Seller name/contact/tax and financial totals still come from the immutable issued
snapshot, never from branding configuration. Rendering a branded invoice does not
change payment, stock or financial history.

Browser A4 printing is distinct from #419's queued private PDF artifacts. That
worker must reuse the print asset with a stored brand/template revision and hash;
existing stored artifacts must never be overwritten when branding changes.
Template revisions `store-invoice-a4-v1` and `store-invoice-a4-v2` retain their
approved print asset (SHA-256 `457401b43c2c484ced56e1858da9c84a0998d86099ab0935e82bad90f69cbcc4`).
The API asset loader and renderer share the same pinned hashes. A future PDF
logo change needs a separate template revision; previously issued snapshots,
pending job identities and stored PDFs are untouched by UI logo edits.
