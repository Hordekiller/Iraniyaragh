# Approved Iran Yaraq assets

Operator-supplied `5ico.png` and `logo type desctop.png` are preserved as
`source/mark.png` and `source/wordmark.png`; manifest source hashes identify the
exact inputs. No redesigned mark, remote font/logo or CDN is introduced.

`node scripts/prepare-brand-assets.cjs` creates transparent size-specific WebP
for UI, PNG browser/touch icons, and a higher-resolution PNG for invoice printing.
`--check` verifies both apps' generated bytes against these inputs and manifest.
This uses the existing pinned API sharp dependency. Originals are not served as
megabyte images on small-screen headers.

Web header/footer/customer-login, Admin authentication/sidebar (compact/full),
browser icons and issued-invoice view/print use these assets. Admin URLs include
its configured base path; print fonts are imported into Next's local asset graph.
Seller name/contact/tax and financial totals still come from the immutable issued
snapshot, never from branding configuration. Rendering a branded invoice does not
change payment, stock or financial history.

Browser A4 printing is distinct from #419's queued private PDF artifacts. That
worker must reuse the print asset with a stored brand/template revision and hash;
existing stored artifacts must never be overwritten when branding changes.
